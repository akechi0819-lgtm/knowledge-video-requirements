# 蓝图契约

## 0. 定位

蓝图 = 按视频顺序排列的**内容大纲**：让创作者确认讲什么、先讲什么，并在确认后作为后续制作的依据。
蓝图以内容大纲为主。它保留用户明确提出的分镜、旁白、素材、渲染及其他要求；未指定的视觉形式和技术做法留待后续制作时决定。

**但「内容大纲」不等于「结构提纲」**：每段必须给出一个观众看完能复述的具体结论，以及支撑它的具体事实。只写「要讲什么层」不算内容。

## 1. 文件与命名

| 项 | 约定 |
|---|---|
| 输入 | `inbox/需求.md`（上游需求归一化的唯一入口） |
| 产物 | `outbox/蓝图_v1.md`、`_v2.md`…（版本号单调递增，不覆盖旧版） |
| 反馈 | `outbox/反馈.md`（追加流水，每条带时间 / 版本 / 段号） |
| 交付 | `outbox/交付.md`（定稿后的蓝图文件，含段落索引） |
| 状态 | `outbox/状态.json`（确认标记、上次运行，UI 用） |
| 运行记录 | `runs/<timestamp>-<action>.json`（引擎、是否真实调用、错误、耗时） |

## 2. 段落编号（最重要）

- 稳定编号 `B01`、`B02`…`B0N`，标题只作人类可读的附注，**不参与定位**。
- **删段留空号，插段用 `B03a` 这类后缀**；不得重排已有编号。后续修改可按编号定位。
- 段落标题格式固定：`### B01｜段落标题`。

## 3. 字段（讲什么必填；关键事实属本片门槛）

| 字段 | 层级 | 内容 |
|---|---|---|
| `讲什么` | **契约必填** | 这段要给出的**具体结论**；不写台词结构、不写镜头、不写「本段负责…」 |
| `画面意图` | 每段填写 | 写清可见的具体对象及其在本段发生的变化；保留用户明确提出的画面要求，不指定动画技术 |
| `关键事实` | 本片门槛（`quality.facts`） | **1–3 条能被复述的硬知识颗粒**（考古遗存、年代地点、可量化变化、机制、文献器物、事件节点） |
| `旁白` | — | 可选。需求自带或能写就写；写不出可留空，**不许用「待创作者补」占位** |
| `备注` | — | 可选。表述边界、待核对项写这里，**不要写进正文当挡箭牌** |

整份文档还需：`主题`（H1「# 蓝图：<主题>」）、`用户明确要求` 列表（无明确要求时写「（无）」）、叙事顺序。

蓝图还包含资产清单 `assets`：按需记录需要保持一致的角色、道具和背景。每项有稳定 `id`、`name`、`type`（`character`、`prop` 或 `background`）、`description` 和关联段号数组 `sections`；没有所需资产时为空数组。Markdown 的「资产清单」下每条以 JSON 对象保存。确认整份蓝图时一并确认此清单；后续生成和确认资产图片仍是单独步骤。

**Markdown 落盘形式**：开启本片门槛时每段多一行 `**关键事实：** 事实一；事实二`（多条用中文分号分隔）；未开启时不出现该行。工具调用时 `sections[].facts` 是字符串数组，渲染器负责拼成这一行。

「讲什么」可能直接用于配音，应自然易懂。出处紧跟对应的关键事实，核查过程留在备注，不在每段讲述或旁白重复脚注、来源或免责声明；必要的不确定性、准确性限定和用户要求的表述边界仍须保留。

## 4. 明确不做（越界）

- 未经用户指定，不擅自确定动画技术、字体、组件、工具、逐帧动作或渲染参数；用户明确提出的要求应保留。
- 不做版本系统、不做局部重生成（PRD 第一版范围）。
- 不改写需求里的事实与「资料与表述边界」。

**关于联网检索（v2.2）**：生成 / 回改支持**按次联网检索**（UI 勾选，默认关）。允许检索的回合，引擎会临时放开 `web_search / web_fetch`，检索到的事实直接写进关键事实、来源写进备注（见 SKILL.md §8a）；命令执行在任何模式下都禁止。运行记录（`runs/*.json`）与 UI 徽标如实标注该次是否联网。

**注意：不做「自动事实核验」≠ 不写具体事实。** 写具体事实是模型的职责：默认凭自身知识写，写不具体且本次允许检索时按 §8a 定向联网补充。不确定处用「约」「距今 X–Y 年」「目前主流看法」表述，并在 `备注` 标注待核对；**绝不允许因为不确定就把整段留空**。

## 5. 校验规则（代码侧硬保证）

`validate` 能力检查两层，**内容层是否开启由插件 config 的 `quality` 决定**（工作台默认关闭）：

**形态层（通用契约，永远开启）**：编号合法性（`^B\d{2}[a-z]?$`）、不重复、首段为 B01、顺序不乱、主题存在、至少 2 段、`讲什么` 齐全；用户要求在分段正文中是否体现（软关键词匹配，未命中给提醒）。

**内容层（本片门槛，`quality.facts: true` 时开启）**：

| 检查 | 级别 | 说明 |
|---|---|---|
| 每段 `关键事实` 少于 `minFactsPerSection` 条 | error | 本片要求每段 ≥1 条 |
| `关键事实` 命中占位话术黑名单 | error | 如「以核对后的资料为准」「待核对」「本段只讲」「观众应能复述」等，见 SKILL.md §5 |
| 某条事实无任何具体锚点 | error | 锚点判定**只用通用规则**：数字 / 年代 / 地理后缀（省、谷、湖、山脉、洞穴…）/ 书名号引号 / 拉丁词 / ≥4 项具体枚举 / 通用证据与科学名词。**不含任何题目专名表** |
| `讲什么` 元叙述密度过高 | warning | 「要让观众…」「这一段负责…」「具体内容放到…」出现多次 |
| 全片含年代 / 数字的事实 < `minDatedFacts` 条 | error | 防「整片没有一条硬信息」（本片要求 ≥2 条） |
| 全片事实条数 < 段落数 | warning | 防知识主体被压扁 |

模型侧的 `write_blueprint` 工具**内置同一个校验器**（同样按 policy 开关）：提交即校验，失败把 `errors` 逐条返回给模型自行修正；服务端落盘前再校验一次，失败自动重试一次。
**真正保证形态的是代码；内容质量 = policy 门槛 + skill 方法论/素材 + 模型能力三者合起来，单靠提示词不行。**

## 6. 叙事配比（v2 新增，写进 skill 而非校验器）

- 钩子 1 段、反差 1–2 段、回扣 1 段；**知识主体必须占全片一半以上段落**。
- 判断方法：哪一段在回答标题里那个问题，哪一段就是重头戏；重头戏不许一段带过。
- v1 曾写「通常 3—5 段」，直接导致 B03 重头戏被压成一段，已废止。配比属于方法论（skill），段数随需求走，不进契约。

## 7. 返工回路

创作者按 `B0N` 指出段落 → `feedback` 写 `反馈.md` → `revise` 回到蓝图整条重出 `vN+1`
（同一 agent 会话接上下文，但**文件才是真相源**）→ 创作者重新确认 → `finalize` 写 `交付.md`。

**反馈说「信息密度低 / 离科普差得远」时，唯一正确的动作是把具体事实写进段落**，不是新增一段「本段将给出证据与变化」。

## 8. 确认后的下一步

创作者确认各段后，可在工作台定稿。`outbox/交付.md` 保存段落索引与完整蓝图，供后续制作参考；定稿不代表视频已经制作。

## 9. 如实标注

每份产物头部记录 `- **引擎：** …`；`runs/*.json` 记录 `engine` / `realCall` / `model` / `errors` / `ms`。
生成失败时如实报告，不使用离线样例代替真实生成。
