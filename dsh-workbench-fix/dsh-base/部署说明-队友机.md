# 部署说明（队友机）

这是一份可直接拷走的 DSH 基座完整包，团队版本锁定 **DSH 0.2.2-rc.1**。拷到任意 Windows 机器后按下面四步即可跑起来。

## 1. 环境要求

- **Node.js ≥ 24.9.0**（`dsh.cmd` 启动时强制检查；DSH rc.1 的会话压缩也需要新版 zstd）。
- **Python 3**（仅场面取证 `scene_retrieval.py` 需要，纯标准库无第三方依赖）。
- Windows（启动器是 .cmd；junction 也只在 Windows 下可用）。

## 2. 安装依赖

```sh
cd dsh-base
npm ci
```

`package-lock.json` 已锁定，不要用 `npm install` 升级依赖。镜像慢可加 `--registry=https://registry.npmmirror.com`。

## 3. 重建 profile junction

zip 里无法携带目录 junction，跑一次：

```sh
setup-profiles.cmd
```

它把两个 profile（`bohack` / `workbench`）的 `node_modules/@bohack/blueprint` 链接到本地的 `packages/bohack-blueprint`。

## 4. 登录 DSH 账号

本机凭据（`.dsh-home/.credentials.yaml`）**不随包分发**。首次启动 `dsh-workbench.cmd` 时按 DSH 的登录引导完成账号授权（用你自己的 DeepSeek 账号），凭据会写到本机的 `.dsh-home/` 下。

## 启动

| 命令 | 用途 |
|---|---|
| `dsh-workbench.cmd` | **主入口**：单实例双会话工作台（需求对话 + 蓝图），UI 在 `http://127.0.0.1:3099/bohack/` |
| `dsh-bohack.cmd` | 仅蓝图模块（临时调试用） |

## 网页里的创作流程

点「新建创作」开始独立话题。左侧选择器可以返回已有创作，带 thread 参数的页面地址也可以用于重开同一创作。聊天、资料、需求单和蓝图保存在 `workspace/threads/<会话 ID>/` 下。明确要求整理后，右栏显示本次需求单；在聊天中要求开始蓝图，或点击「起草蓝图」，均使用本次需求。

## 包内结构速览

- `packages/bohack-blueprint/` — A 模块本体（九能力 service、蓝图引擎、契约工具 `read_requirement`/`query_scene`、墨影书斋 UI）。
- `.dsh-home/profiles/` — 两个 profile 定义（bohack = 蓝图；workbench = 双会话工作台，叠加了 C 的工具面 patch）。
- `workspace/` — 文件真相源：`inbox/`（需求单）、`outbox/`（蓝图版本）、`refs/`（场面索引净区）、`sources/`（资料脏区）、`.agents/skills/`（blueprint 方法论 + 队友的 knowledge-video-requirement skill）、`handover/`（C 交接包原件）、`rules/`、`A-USAGE.md`（模块用法与验收记录）、`ARCH-HOST-COMMUNICATION.md`（宿主通信架构决策）。
- `.git/` — 完整 git 历史（commit 从基线到契约工具落地）。
- `DSH-VERSION-RUNBOOK.md` — 版本锁定的来龙去脉。

## 注意

- **不要提交/外传任何密钥**：`.dsh-home/.credentials.yaml`、`sessions/`、`storages/` 已被 .gitignore 钉死，zip 里也没有。
- `workspace/runs/`（运行日志）不随包分发，首跑自动重建。
- 改动请走 git 提交，别直接改 vendor 的 `scene_retrieval.py`（它是 C 模块的原件拷贝）。

## 三模块联调与成片

本工作台使用 DSH 基座的网页对话和段落确认，调用独立的 `video-kit` 生产成片。随队交接的两份 2026-11-14 状态分别记录 Windows DSH 基座的环境、需求契约，以及桌面轨的火锅样片、正式 v1 与返工预览。各轨的版本确认只属于原来的创作。这里从当前创作的定稿重新导出，保留蓝图段号、旁白与成片的实测时间区间。

1. 把 `video-kit` 放在本项目约定的 `../../video-kit`，或指定 `VIDEO_KIT_DIR`。在 kit 目录按其 README 安装 Playwright、Python 依赖及 ffmpeg/ffprobe，准备可用的 Chrome、Edge 或 Chromium。
2. 场景设计使用 OpenAI 兼容的 Chat Completions 接口。设置 `SCENE_ENDPOINT`（完整接口 URL）、`SCENE_MODEL`、`SCENE_API_KEY`。macOS 启动器对 DeepSeek 官方接口可复用当前 DSH Home 的 DeepSeek 凭据。自定义接口需单独提供对应凭据。
3. macOS 在本目录运行 `./dsh-workbench.sh`，打开 `http://127.0.0.1:3099/bohack/`。正式配音应配置服务和音色。未显式选择本机音色时，启动器默认沿用 video-kit 的在线语音设置。可用 `VIDEO_VOICE` 指定配音方式，Windows 可选 `sapi`，API 配音可选 `api:<音色>` 并配置 kit 的 TTS 接口。
4. 在新创作中说出主题、补充素材，明确说“整理需求，起草蓝图”。在蓝图页审阅每段的讲述、画面意图和旁白；修改后以当前版本为准。在对话里说“全部确认”即可定稿，说“全部确认，开始制作”可同时启动制作。蓝图页的「全部确认并开始制作」可一次启动整个流程。「仅确认定稿」会进入成片页，方便先选择视觉风格。
   使用 DSH 内置模型绘制素材和设计动画时，启动前设置 `SCENE_MODE=dsh`，确保同一环境的 `dsh headless` 可以调用已配置的 DeepSeek 模型。
   蓝图中的动画素材清单随段落一起定稿。开始制作时，工作台沿用本版本选定的视觉风格，未选择时使用「简洁知识图解」。后台生成缺少的素材，复用本版同风格的已有素材，接着制作成片。
5. 制作进度、失败原因、播放器、MP4 和段落映射均在成片页。每次制作保存于本创作的 `production/<任务 ID>/`。映射的 `blueprint_id` 对应人读蓝图，`start_sec/end_sec` 是成片秒数。自动质检覆盖文件解码、时间区间、人声、音乐及静帧；画面是否正确表达知识点仍需看样片。

## 项目模型与风格库

工作台默认采用四组通用制作方法，覆盖来源核对、旁白审阅、时间线检查和逐句画面对照。「风格 Skill 管理」用于查看内置风格、导入本机的 SKILL.md、从公开 GitHub 的 SKILL.md 文件地址载入正文，或粘贴社交平台上看到的设计规则并注明出处。导入的是规则文本；仓库中的脚本、字体和模板不会自动安装。个人库可跨创作使用。蓝图定稿后，在成片页点选风格名称，工作台保存本版制作使用的规则快照。如需换风格，在同一版重新选择即可。已导出的成片由下一次制作更新。

「从参考视频学习」使用 FFprobe 读取时长、FFmpeg 抽帧，将按时间排列的画面交给支持图片输入的模型。确认可复用的规则后再保存为个人 Skill。它不训练模型权重，也不分析音轨；快速剪切、连续运镜和精确转场不能仅据抽帧确定。

在启动进程环境（Windows 也可设置同名环境变量）挂载兼容 OpenAI Chat Completions 的项目模型。macOS/Linux 也可在本机私有的 `.dsh-home/workbench-model.env` 中填写。

远端接口配置 `WORKBENCH_MODEL_KEY`，不要提交密钥。项目模型供风格学习和通用画面制作使用；如通用模型只支持文本，可将学习单独指向视觉模型（`WORKBENCH_VISION_ENDPOINT`、`WORKBENCH_VISION_MODEL`、`WORKBENCH_VISION_KEY`）。使用远端视觉接口时，参考视频的抽帧会发送给该服务。画面生成如另有供应商，使用 `SCENE_ENDPOINT`、`SCENE_MODEL`、`SCENE_API_KEY`。需求和蓝图对话仍经 DSH 原有的工具调用会话；不会随视觉模型切换。已选风格的工程使用通用场景生成器，旧版火锅成片仍可按 README 的专用脚本复现。
