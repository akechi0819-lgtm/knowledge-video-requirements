# 部署说明（队友机）

日常体验直接打开 https://jiangjie.gingers.cloud/，无需安装。以下步骤用于开发与自托管重建本地调试环境，团队版本锁定 **DSH 0.2.2-rc.1**。

## 1. 环境要求

- **Node.js ≥ 24.9.0**（`dsh.cmd` 启动时强制检查；DSH rc.1 的会话压缩也需要新版 zstd）。
- **Python 3**（仅场面取证 `scene_retrieval.py` 需要，纯标准库无第三方依赖）。
- Windows（启动器是 .cmd；junction 也只在 Windows 下可用）。

## 2. 安装依赖

```sh
cd dsh-base
npm ci
```

`package-lock.json` 已锁定，不要用 `npm install` 升级依赖。镜像慢可加 `--registry=https://registry.npmmirror.com`。

## 3. 重建 profile junction

zip 里无法携带目录 junction，跑一次：

```sh
setup-profiles.cmd
```

它把两个 profile（`bohack` / `workbench`）的 `node_modules/@bohack/blueprint` 链接到本地的 `packages/bohack-blueprint`。

## 4. 登录 DSH 账号

本机凭据（`.dsh-home/.credentials.yaml`）**不随包分发**。首次启动 `dsh-workbench.cmd` 时按 DSH 的登录引导完成账号授权（用你自己的 DeepSeek 账号），凭据会写到本机的 `.dsh-home/` 下。

## 启动

| 命令 | 用途 |
|---|---|
| `dsh-workbench.cmd` | **主入口**：单实例三角色工作台（需求对话 + 蓝图 + 视频制作），UI 在 `http://127.0.0.1:3099/bohack/` |
| `dsh-bohack.cmd` | 仅蓝图模块（临时调试用） |

## 网页里的创作流程

点「新建创作」开始独立话题。左侧选择器可以返回已有创作，带 thread 参数的页面地址也可以用于重开同一创作。聊天、资料、需求单和蓝图保存在 `workspace/threads/<会话 ID>/` 下。明确要求整理后，右栏显示本次需求单；在聊天中要求开始蓝图，或点击「起草蓝图」，均使用本次需求。

## 包内结构速览

- `packages/bohack-blueprint/` — A 模块本体（九能力 service、蓝图引擎、契约工具 `read_requirement`/`query_scene`、墨影书斋 UI）。
- `.dsh-home/profiles/` — 两个 profile 定义（bohack = 蓝图；workbench = 双会话工作台，叠加了 C 的工具面 patch）。
- `workspace/` — 文件真相源：`inbox/`（需求单）、`outbox/`（蓝图版本）、`refs/`（场面索引净区）、`sources/`（资料脏区）、`.agents/skills/`（blueprint 方法论 + 队友的 knowledge-video-requirement skill）、`handover/`（C 交接包原件）、`rules/`、`A-USAGE.md`（模块用法与验收记录）、`ARCH-HOST-COMMUNICATION.md`（宿主通信架构决策）。
- `.git/` — 完整 git 历史（commit 从基线到契约工具落地）。
- `DSH-VERSION-RUNBOOK.md` — 版本锁定的来龙去脉。

## 注意

- **不要提交/外传任何密钥**：`.dsh-home/.credentials.yaml`、`sessions/`、`storages/` 已被 .gitignore 钉死，zip 里也没有。
- `workspace/runs/`（运行日志）不随包分发，首跑自动重建。
- 改动请走 git 提交，别直接改 vendor 的 `scene_retrieval.py`（它是 C 模块的原件拷贝）。

## 三模块联调与成片

本工作台使用 DSH 基座的网页对话和段落确认，调用独立的 `video-kit` 生产成片。随队交接的两份 2026-11-14 状态分别记录 Windows DSH 基座的环境、需求契约，以及桌面轨的火锅样片、正式 v1 与返工预览。各轨的版本确认只属于原来的创作。这里从当前创作的定稿重新导出，保留蓝图段号、旁白与成片的实测时间区间。

1. 把 `video-kit` 放在本项目约定的 `../../video-kit`，或指定 `VIDEO_KIT_DIR`。在 kit 目录按其 README 安装 Playwright、Python 依赖及 ffmpeg/ffprobe，准备可用的 Chrome、Edge 或 Chromium。
2. 开发版的默认「视频 Agent」使用独立 DSH 会话，按已定稿蓝图和资料页的素材关联编写各段 HTML/CSS/JavaScript。它通过工作台工具取得实际配音时长、预览画面、合成、质检并提交。选择「原结构化模式」时，场景设计使用 OpenAI 兼容的 Chat Completions 接口。设置 `SCENE_ENDPOINT`（基础地址或完整 Chat Completions 接口 URL）、`SCENE_MODEL`、`SCENE_API_KEY`。macOS 启动器对 DeepSeek 官方接口可复用当前 DSH Home 的 DeepSeek 凭据。自定义接口需单独提供对应凭据。
3. macOS 在本目录运行 `./dsh-workbench.sh`，默认地址为 `http://127.0.0.1:3109/bohack/`；Windows 运行 `dsh-workbench.cmd`，默认端口 3099。可用 `WORKBENCH_PORT` 指定端口。正式配音应配置服务和音色。未显式选择本机音色时，启动器默认沿用 video-kit 的在线语音设置。可用 `VIDEO_VOICE` 指定配音方式，Windows 可选 `sapi`，API 配音可选 `api:<音色>` 并配置 kit 的 TTS 接口。
4. 在首页选「制作风格 / Skill」，或在左栏说「用像素风讲这个主题」。需求单和分段蓝图页也可改选。已有草稿时，点「按此 Skill 重新起草」生成新版。说出主题、补充素材后，明确说“整理需求，起草蓝图”。在蓝图页审阅每段的讲述、画面意图和旁白；修改后以当前版本为准。在对话里说“全部确认”即可定稿，说“全部确认，开始制作”可同时启动制作。蓝图页的「全部确认并开始制作」可一次启动整个流程。「仅确认定稿」会进入成片页，方便先选择视觉风格。
   原结构化模式如需使用独立的 DSH 调用设计画面，启动前设置 `SCENE_MODE=dsh`，确保同一环境的 `dsh headless` 可以调用已配置的 DeepSeek 模型。
   蓝图会把每段建议的角色、道具或背景登记到资料页。「各段用到的素材」显示当前关联，点击名字即可打开同一条资料。老师可以在资料页上传图片或生成并确认素材，勾选、修改或清空它要出现的段落。蓝图已定稿也可以调整素材关联，下次制作会采用新的分配。没有实物的声明按段传给场景设计；参考资料只供理解内容。
5. 成片页的「生成素材」把声明送到素材生成工具，产出候选。作者确认后可在多个段落使用同一版本。尚无实物的声明也可由制作 Agent 在场景代码里表现。成片完成后，在返工框写明段落与意见或在需求对话中提出修改。返工会新建制作会话，读取已有段落源码，完成后可对照上一版或下载源码包。
6. 制作中断后，在左栏问“制作停在哪一步了？”可查看阶段和错误。说“检查一下是不是素材丢了”会核对本创作的文件；需要补图时，在成片页生成并确认对应素材，再恢复制作。蓝图指定的上传原图丢失时，按提示补传原件后再说“继续制作”。
   制作进度、失败原因、播放器、MP4 和段落映射均在成片页。每次制作保存于本创作的 `production/<任务 ID>/`。映射的 `blueprint_id` 对应人读蓝图，`start_sec/end_sec` 是成片秒数。自动质检覆盖文件解码、时间区间、人声、音乐及静帧；画面是否正确表达知识点仍需看样片。

## 项目模型与风格库

云端通用模型优先适配 GPT 6.1 Terra，需求、蓝图、视频代码和预览截图使用同一模型；配音继续独立使用小米。在 `/opt/jiangjie-preview/model.env` 为网关配置 `BOHACK_CLOUD_BASE_URL`（实际 API 根地址）、`BOHACK_CLOUD_MODEL`（实际模型 ID）、`BOHACK_CLOUD_API`（默认 `openai-responses`，Chat Completions 接口则填 `openai-completions`），以及 `BOHACK_CLOUD_REASONING`（默认 `low`）。网关只传递连接配置，每个浏览器实例的通用模型 Key 仍通过工作台设置独立填写。TTS 设置单独填写小米 Key，保持 `mimo-v2.5-tts` 与其音色。Worker 使用讲界自身的应用标识，不携带 MiMo 专属思考参数。

2026-11-18 在每实例 1 核、1 GB 的服务器上，并发实测 Terra + 小米 TTS：默认方法生成 12.7 秒视频，制作耗时 305.637 秒，其中配音 8.474 秒、模型与网络等待 179.733 秒、预览截图 10.600 秒、渲染合成 102.355 秒、技术检查约 3.414 秒；完整项目 Skill 生成 17.367 秒视频，耗时 502.400 秒。两次基础播放、音轨与段落检查正常，但分别保留两段、一段长静帧提示。以上是减轻默认审片要求前的实测，不代表修改后的速度；取片与本机快照传输另计。服务器清空测试实例后，已从本机快照恢复并下载同一 MP4，SHA-256 一致。

模型结束一轮回复不代表制作完成：尚未提交、且本轮已有真实工具进展时，沿用同一会话继续；续做无工具进展、模型报错或会话中止时明确失败。

默认每段只查看一张代表性预览，审片一轮即可；仅脚本或播放错误、主体缺失、严重遮挡自动修复，并只复查受影响段。静帧和审美建议不拦交片，不自动触发返工。

最终 `submit` 工具一次完成渲染、基础检查和提交；渲染或质检报错时不会归档为完成，不再要求模型在合成后额外调用一个空提交工具。画面预览与必要修正仍在最终提交前完成。

单核云端 Worker 的截帧并发设为 1，仍保留 1280×720、30fps 和既有截图质量；本地默认并发仍为 3。原来云端同时开三个画页，会触及容器的进程／线程上限并导致浏览器崩溃。默认四组方法直接随任务提供，视频会话不再重复加载原生 Skill 工具；单篇方法没有附带文件时不提供资料读取工具。选择项目 Skill 时，从镜像里的公共只读目录按需读参考资料，避免将整套公共资源打包进用户项目。

工作台默认采用四组通用制作方法，覆盖来源核对、旁白审阅、时间线检查和逐句画面对照。「风格 Skill 管理」用于查看内置风格、导入本机的 SKILL.md、从公开 GitHub 的 SKILL.md 文件地址载入正文，或粘贴社交平台上看到的设计规则并注明出处。导入的是规则文本；仓库中的脚本、字体和模板不会自动安装。个人库可跨创作使用。起草时保存本版的 Skill 规则；蓝图、章节预览和成片场景按它安排构图、文字、配色及动效。成片完成后，可以说“换成像素画风重绘”。只说“换个画风”时，会打开风格库；接着点选或回复风格名即可启动重绘，也可说“取消重绘”。工作台使用原蓝图重做画面，按文本和配音配置核对可复用的旁白。

「从参考视频学习」使用 FFprobe 读取时长、FFmpeg 抽帧，将按时间排列的画面交给支持图片输入的模型。确认可复用的规则后再保存为个人 Skill。它不训练模型权重，也不分析音轨；快速剪切、连续运镜和精确转场不能仅据抽帧确定。

在启动进程环境（Windows 也可设置同名环境变量）挂载兼容 OpenAI Chat Completions 的项目模型。macOS/Linux 也可在本机私有的 `.dsh-home/workbench-model.env` 中填写。

设置页首先展示通用文本/代码与配音两类配置；云端预览统一使用服务器配置的多模态模型，本地运行时可在高级设置分别指定需求、蓝图和视频会话的 provider/model。素材生成、章节示意图和参考风格分析也可在高级设置覆盖项目模型。生图接口暂未接入制作，无需配置。作者点击确认只记录所选版本。配音可独立选择 MiMo 或兼容 OpenAI Speech 的服务；“茉莉”仅为 MiMo 预设，其他服务填写自己的音色 ID。仅同一服务商可选择共用文本 Key，否则单独配置配音 Key。

远端接口配置 `WORKBENCH_MODEL_KEY`，不要提交密钥。项目模型供风格学习和通用画面制作使用；如通用模型只支持文本，可将学习单独指向视觉模型（`WORKBENCH_VISION_ENDPOINT`、`WORKBENCH_VISION_MODEL`、`WORKBENCH_VISION_KEY`）。使用远端视觉接口时，参考视频的抽帧会发送给该服务。画面生成如另有供应商，使用 `SCENE_ENDPOINT`、`SCENE_MODEL`、`SCENE_API_KEY`。需求、蓝图、视频制作各自使用独立 DSH 会话，可在设置中分别选择 provider/model；素材生成、章节预览和风格学习也可单独配置工具模型，不随视觉模型自动切换。默认 Agent 模式编写场景代码，原结构化模式仍使用图层数据生成器；旧版火锅成片可按 README 的专用脚本复现。
